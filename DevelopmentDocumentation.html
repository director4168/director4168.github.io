项目概述

本站基于 HTML5、JS ES6 (ECMAScript 2015)、CSS3 的纯静态前端网站，几乎不支持 IE 系列内核。使用 MPL-2.0 开源协议。

语言切换按钮、主题切换按钮，请勿持续长按，这可能会导致锁定！

核心依赖：Material Icons（图标）、highlight.js（代码高亮）、思源宋体（字体）。

使用建议

  • 优先使用 .site-panel 承载正文中的独立内容块，不要用大量内联样式临时拼面板。
  • 默认上下间距已经在 CSS 中统一设置，一般不要在 HTML 中重复添加 margin-top 或 margin-bottom。
  • 整页正文面板建议使用 .site-panel.doc-content-panel 包裹在 .main-wrap 内，外侧间距由 .main-wrap 控制，避免额外套多层面板造成边距不一致。
  • 面板标题建议使用简短文字，图标仅作为视觉辅助，不要只放图标不放文字。
  • 面板内部放按钮时推荐使用 .site-action-row，放状态标签时推荐使用 .site-status-chip-row。
  • 不建议多层嵌套 .site-panel，如果需要分区，可以在同一面板内使用标题、分割线或多个行容器。

跳转卡片 List Item

有两种类型：弹窗确认型（点击后弹窗，确认后跳转）和纯展示型（无弹窗，仅涟漪+圆角动画）。两者共享相同的视觉交互效果。

链接修复

所有 a.list-item 的 href 属性在运行时由 CoreLogic.js 自动移除，以防止移动端浏览器的长按链接预览导致页面锁定。HTML 中仍需写 href="javascript:void(0);" 以保持语义。

涟漪效果

点击时从触点位置产生圆形涟漪向四周扩散，扩散期间保持浅蓝色（--md-color-highlight），松手后 0.3s 淡出消失。

  • 按下：涟漪从触点扩散，已扩散部分持续保持浅蓝色
  • 释放/移出：0.3s 淡出
  • 同时触发圆角变化（四角变圆润）
  • 内容层（图标、文字）始终显示在涟漪之上

CSS 关键属性

  • position: relative; overflow: hidden：涟漪定位与裁切
  • touch-action: manipulation：禁止浏览器长按菜单
  • -webkit-touch-callout: none：禁止 iOS 链接预览
  • transition: border-radius 0.1s：精确属性过渡，不用 all

Toast 弹窗 / 轻提示

Toast 是一种轻量级提示弹窗，用于显示“复制成功”“保存完成”“操作失败”等短消息。它不会阻塞页面，不需要用户点击确认，通常在显示一段时间后自动消失。本站原版 Toast 主要由 AdditionalStyles.css 中的 .site-toast 样式提供外观与动画，JavaScript 只负责修改文本、添加/移除 .show 类。

适用场景

  • 成功反馈：复制成功、保存成功、已刷新。
  • 轻量提醒：当前功能不可用、需要先选择项目。
  • 非阻塞提示：不希望打断用户操作时，优先使用 Toast，而不是 MD3 确认弹窗。
  • 临时状态：调试页中的“开始检测”“自检完成”等状态消息。

结构模型

Toast 由三部分组成：显示载体、触发元素、控制逻辑。显示载体负责展示，触发元素负责声明内容，控制逻辑负责读取内容并切换 .show 类。

组成 示例 作用
显示载体 <div class="site-toast" id="pageToast"> 真正显示在页面底部的 Toast 框。
触发元素 <button data-toast="保存成功"> 像跳转卡片一样，在自身声明要显示的 Toast 文本。
控制逻辑 showToast() + [data-toast] 绑定 读取 data-toast，写入载体并控制显示/隐藏。

  • 页面中建议只保留一个 Toast 显示载体，通过 JS 动态修改文本。
  • 静态按钮优先使用 data-toast 声明内容，动态业务结果再直接调用 showToast()。
  • Toast 文本尽量简短，建议控制在一行或两行内。
  • 不要把重要确认、协议内容或危险操作提示放进 Toast；这些场景应使用 MD3 弹窗。
  • 使用 textContent 设置内容，避免直接写入未过滤的 HTML。

搜索系统工作原理

  1. 页面加载后自动绑定搜索输入框
  2. 输入内容会进行小写化、空白合并和 Unicode 兼容标准化
  3. 遍历目标元素，只收集标题和副标题这类外部展示文本作为搜索文本
  4. 匹配项保留显示，不匹配项添加 .search-hidden
  5. 匹配项中的标题和副标题会用 mark.search-highlight 高亮关键词
  6. 如果容器内没有可见项，则隐藏对应 .card 或 .card-section
  7. 无结果时显示空结果提示，并在搜索框上添加无结果状态

搜索系统 API

  • window.SiteSearch.init()：初始化并绑定页面中的搜索框
  • window.SiteSearch.refresh()：重新绑定搜索框，适合动态插入搜索框或卡片后调用
  • window.SiteSearch.apply(input)：对指定输入框立即执行一次搜索过滤

注意事项

  • 搜索框建议放在 .main-content 内，否则会回退到 body 作为搜索根节点
  • 清除按钮、统计文本和空结果提示由 Search.js 自动创建，不需要手写
  • 隐藏状态统一使用 .search-hidden，不要再依赖 inline display:flex 判断可见项
  • 如果需要让某个关键词可被搜到，应把它显示在卡片标题或副标题中

  • 进度阈值 0.5：大于则吸附打开，否则吸附关闭

Cookie.js — 协议检查

页面加载时自动检查用户是否已同意协议。未同意则跳转到 Agreement.html。

  • 已同意（cookie_agreement=agreed）→ 正常浏览
  • 未同意且不在 Agreement.html → 自动跳转
  • 自动适配非根目录路径（计算 ../ 深度）
  • agreeAndContinue() 设置永久 Cookie（2 年有效期）后跳转首页

Cookie.js 工作原理

  1. 页面加载时检查 cookie_agreement Cookie
  2. 如果 Cookie 存在且值为 agreed，则正常浏览
  3. 如果 Cookie 不存在或值不是 agreed，则跳转到 Agreement.html
  4. 在 Agreement.html 页面，用户点击同意按钮后调用 agreeAndContinue()
  5. agreeAndContinue() 设置 Cookie 并跳转到首页

Cookie.js 配置选项

Search.js — 搜索过滤

  • 自动绑定 #SearchInput、.search-InputBox、[data-search-input]
  • 只匹配卡片外部展示的 .list-title 和 .list-subtitle 文本
  • 不会匹配 data-title、data-content、data-href 等弹窗或跳转数据
  • 无匹配项会添加 .search-hidden，容器内无匹配项时隐藏整组卡片
  • 自动生成清空按钮、匹配统计、空结果提示和关键词高亮
  • 按 Esc 可清空当前搜索框并恢复全部显示

Search.js 工作原理

  1. 页面加载后执行初始化，查找可绑定的搜索输入框
  2. 根据 data-search-root 或最近的 .main-content 确定搜索根节点
  3. 根据 data-search-target 查找目标项，默认目标为 .list-item
  4. 规范化关键词，并从每个目标项的标题和副标题中收集搜索文本
  5. 匹配失败的目标项添加 .search-hidden，匹配成功的目标项恢复显示
  6. 匹配成功时在标题和副标题文本中插入 mark.search-highlight
  7. 刷新匹配统计、搜索框状态和空结果提示

  • 动态插入卡片或搜索框后调用 window.SiteSearch.refresh()
  • 不要通过 inline display 判断搜索结果，统一使用 .search-hidden
