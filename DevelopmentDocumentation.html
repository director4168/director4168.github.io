项目概述

本站基于 HTML5、JS ES6 (ECMAScript 2015)、CSS3 的纯静态前端网站，几乎不支持 IE 系列内核。使用 MPL-2.0 开源协议。

语言切换按钮、主题切换按钮，请勿持续长按，这可能会导致锁定！

核心依赖：Material Icons（图标）、highlight.js（代码高亮）、思源宋体（字体）。

  • 纯静态：无需服务器，可直接部署到 GitHub Pages
  • 响应式设计：适配移动端和桌面端
  • 主题切换：支持亮色/暗色主题
  • 模块化设计：CSS 和 JS 文件分离，便于维护

  3. 修改内容：修改标题、描述、链接等
  4. 添加链接：在首页或其他页面添加指向新页面的链接
  5. 测试功能：确保所有功能正常工作

常见问题解答

  • Q: 为什么我的页面没有样式？
    A: 检查是否正确引入了 CSS 文件，特别是 MainColorStyle_Default.css 和 AdditionalStyles.css
  • Q: 为什么主题切换不工作？
    A: 确保页面中有 id="themeToggle" 的元素，并且正确引入了 CoreLogic.js
  • Q: 为什么弹窗不显示？
    A: 确保页面中有 id="md3Dialog" 的弹窗容器，并且正确引入了 CoreLogic.js

跳转卡片 List Item

有两种类型：弹窗确认型（点击后弹窗，确认后跳转）和纯展示型（无弹窗，仅涟漪+圆角动画）。两者共享相同的视觉交互效果。

链接修复

所有 a.list-item 的 href 属性在运行时由 CoreLogic.js 自动移除，以防止移动端浏览器的长按链接预览导致页面锁定。HTML 中仍需写 href="javascript:void(0);" 以保持语义。

涟漪效果

点击时从触点位置产生圆形涟漪向四周扩散，扩散期间保持浅蓝色（--md-color-highlight），松手后 0.3s 淡出消失。

  • 按下：涟漪从触点扩散，已扩散部分持续保持浅蓝色
  • 释放/移出：0.3s 淡出
  • 同时触发圆角变化（四角变圆润）
  • 内容层（图标、文字）始终显示在涟漪之上

CSS 关键属性

  • position: relative; overflow: hidden：涟漪定位与裁切
  • touch-action: manipulation：禁止浏览器长按菜单
  • -webkit-touch-callout: none：禁止 iOS 链接预览
  • transition: border-radius 0.1s：精确属性过渡，不用 all

主题切换系统

支持 亮色 (light) 和 暗色 (dark) 双主题。所有配色通过 MainColorStyle_Default.css 中的 CSS 变量控制。

工作机制

  1. 页面默认 <body class="dark-theme">（暗色）
  2. CoreLogic.js 检查 localStorage.userTheme：有记忆且在 10 分钟内 → 使用记忆主题
  3. 无记忆 → 跟随系统 prefers-color-scheme
  4. 点击 #themeToggle 切换：保存到 localStorage + 同步切换图标（dark_mode ↔ light_mode）

CSS 变量体系

亮色变量定义在 :root，暗色覆盖在 body.dark-theme。详见 CSS 变量参考。

主题切换使用场景

  • 用户偏好：让用户选择喜欢的主题
  • 环境适应：根据环境光线自动切换
  • 无障碍访问：提供高对比度主题

菜单按钮交互

菜单按钮（≡）支持两种操作：

  • 点击：切换侧滑栏打开/关闭
  • 水平滑动：在按钮上触摸/鼠标水平滑动，侧滑栏跟随滑动距离实时展开，菜单图标同步旋转（0°~90°）。松手后根据进度吸附到打开或关闭状态。

动画关键点：

  • 侧滑栏位移和图标旋转角度跟随进度实时更新
  • 拖动时 CSS transition 临时禁用，松手后恢复
  • 遮罩透明度跟随展开进度
  • 进度阈值 0.5：大于则吸附打开，否则吸附关闭

Cookie.js — 协议检查

页面加载时自动检查用户是否已同意协议。未同意则跳转到 Agreement.html。

  • 已同意（cookie_agreement=agreed）→ 正常浏览
  • 未同意且不在 Agreement.html → 自动跳转
  • 自动适配非根目录路径（计算 ../ 深度）
  • agreeAndContinue() 设置永久 Cookie（2 年有效期）后跳转首页

Cookie.js 工作原理

  1. 页面加载时检查 cookie_agreement Cookie
  2. 如果 Cookie 存在且值为 agreed，则正常浏览
  3. 如果 Cookie 不存在或值不是 agreed，则跳转到 Agreement.html
  4. 在 Agreement.html 页面，用户点击同意按钮后调用 agreeAndContinue()
  5. agreeAndContinue() 设置 Cookie 并跳转到首页

Cookie.js 配置选项

  • agreed：Cookie 值

  • 确保 Agreement.html 页面存在
  • 不要修改 Cookie.js 的核心逻辑
  • 可以通过修改 Cookie 名称和值来自定义
